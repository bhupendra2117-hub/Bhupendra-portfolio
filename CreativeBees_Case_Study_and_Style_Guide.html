Overview

The challenge

CreativeBees grew quickly. Each new AI capability arrived as its own screen, with its own header, colours, buttons and loading behaviour. By 2026 there were more than 20 creation tools, and every one of them looked and behaved a little differently.

Users had to relearn the interface every time they switched tools. Dark previews made white garments disappear. Full-screen loaders blocked work during long AI generations. Arabic layouts and Dark mode were added late, screen by screen.

Design goals

What the redesign had to do

  • Learn once, use everywhere. Every studio follows the same layout and lifecycle.
  • Make AI progress visible. Show each output as it arrives instead of a blocking spinner.
  • Protect the product image. Garments and cutouts must read clearly in either theme.
  • Two full themes and two scripts. Light and Dark, LTR and RTL, all from the same components.
  • No behaviour changes. Teams relied on these tools every day, so the visual redesign could not change how any tool worked.

Key user flows

The same lifecycle, adapted per job

All studios follow Listing → Set up → Generate → Review → Refine → Deliver. These four show how the pattern bends to very different jobs.

Power Content: PDP image set

Catalog & merchandising
  1. Upload product images or sheet
  2. Review slide roles & claims
  3. Watch 8 slides stream in
  4. Regenerate single slides
  5. Gallery & ZIP download

Design decision: a regenerated slide never changes the slides the user has already approved. In Amazon PDP mode, the user picks the hero image (A) in the source list without reordering the uploads, and the canvas labels outputs A–J to match marketplace slots.

Banner AI: campaign banner

Campaign marketer
  1. Pick template & style
  2. Generate scene
  3. Edit layers: text, offer, colour
  4. Approve
  5. Resize to every channel

Design decision: the generated output is rebuilt as editable layers, so a typo or a price change costs one edit instead of a new generation. Arabic offers keep their number order in the editor and in the export.

TechPac: vendor tech pack

Product designer / sourcing
  1. Upload garment
  2. Fabric & AI outline
  3. Artwork crop
  4. Pantone colours & age groups
  5. Export PDF

Design decision: a guided step-by-step flow, because a missed field means a wrong garment at the vendor. The sketch canvas stays light in Dark mode so line work and colours are judged accurately.

Emailer Converter: Figma to HTML

Campaign marketer
  1. Upload .fig file
  2. Slice & render
  3. Switch locale tab
  4. Edit text, images, links
  5. Export HTML

Design decision: locale tabs (UAE and KSA, English and Arabic) sit above one shared canvas. Switching to an Arabic tab changes the layout to right-to-left, so the user edits one email instead of four copies.

Responsive rules

R1No sideways page scroll

The page never scrolls horizontally. Only tables, canvases and timelines may be wider, each inside its own scroll container.

R240px touch targets

Buttons, selects and filters are 40px tall at every width, so they work with a thumb as well as a mouse.

R3Wrap, don't shrink

Toolbars and header actions wrap to a new row instead of shrinking text. Body text stays at 14px or larger.

R4The preview keeps its ratio

Preview wells and output slots keep their aspect ratio and never exceed the column width, so product images are never cropped or stretched.

R5Modals fit the screen

Modals size to the dynamic viewport height, so mobile browser bars never hide the footer actions.

R6RTL at every width

Arabic layouts mirror at every breakpoint, including stacked mobile panels and chip rows that scroll sideways.

Test widths

  • 1440 × 900 main desktop design width
  • 1366 × 515 laptop with browser toolbars open, for short-height checks
  • 834 × 1194 tablet portrait
  • 390 × 844 mobile, checked for clipping, overlap and horizontal overflow

Known gap

Below 769px the sidebar is hidden and there is no menu button yet, so mobile users reach other pages through global search. A slide-out menu drawer is the next responsive improvement.

Interaction, accessibility and localisation

Details that make long AI tasks feel safe

Progress you can see

Results stream in one at a time. Each slot shows its own state, so a single failure doesn’t hide the outputs that succeeded.

Errors that explain

A shared error helper turns API failures into plain messages that say what went wrong and what to try next.

Card action menus

Gallery cards have one overflow menu. It closes when the user clicks outside it or presses Escape.

Fast transitions

A studio’s code starts loading when the user hovers or focuses “Create new”, so the editor opens without a wait.

Contrast and focus

Every control has a visible 3px focus ring (cb-focus at 42%). Button labels keep strong contrast in both themes.

Arabic and RTL

Arabic editors and emailers switch to right-to-left layout, and numbers in offers keep their correct order.

Responsive

Screens are checked at desktop and at 390×844 mobile for clipping, overlap and horizontal scroll. Modals use the full height of the screen.

Reduced motion

Shimmer and entrance animations stop when the user’s system asks for reduced motion.

Guidelines

Rules for new screens

Follow these so new designs match the app and need no new CSS.

Do

  • Design every screen in Light and Dark using the cb variables.
  • Use one primary button per view; the rest are secondary or ghost.
  • Start listing pages with title, description and a Create button, then a toolbar card and a 4-column grid.
  • Start tool pages with a back button and title, then settings cards and a preview.
  • Put generated images and video on the stage well (cb-stage-well: #EEF1F7 Light, #11131A Dark), never straight on the page background.
  • Use the 4px grid: gaps 8, 12, 16; card padding 16–20.

Don’t

  • Add new hex colours, gradients or fonts. Ask for a new cb token instead.
  • Use the old dark-only colours: #805AF5, #21242D, #2B2D3C, #3E414B, #BCC3D7.
  • Use display fonts (Bungee, Monoton, Syne…) in the app UI; they are for banner output only.
  • Put white text smaller than 14px bold on the dark-theme purple (#9B7CF4); contrast is only about 3:1.

Outcomes

What changed

  • More than 20 studios now share one layout, one header and one lifecycle.
  • Light and Dark themes work on every redesigned screen, from one token set.
  • Long AI jobs show progress output by output instead of blocking the page.
  • Arabic and right-to-left layout are part of the components, not added per screen.
  • The redesign shipped without changing how any tool behaves.
Learnings

What I’d carry forward

  • Design the waiting. In AI tools, the generation state gets more screen time than the result.
  • Tokens before screens. Theming one screen at a time doesn’t scale. A shared token layer does.
  • The product image comes first. The stage follows the theme, but it always sits apart from the page so cutouts keep a clear edge.
  • Listings matter as much as editors. People reopen earlier work more often than they start new work.

Scope note. This study covers the user-facing Workspace, Image AI, Smart AI and Video AI sections. It leaves out the Manage section: Master, admin, configuration, credit and reporting pages.
